# Forward-slash repo identifiers, even on Windows

`gig list`, `gig cd`'s picker labels, and the `[debug] found repo: ...` log line all display a repo's location as a relative `host/owner/repo` identifier - the same string `gig config category`'s patterns are documented and written to match against (e.g. `^github\.com/merikan/`), and the same shape the README uses throughout. These identifiers were being rendered with plain `Path::display()`, which uses the OS-native separator - correct for a real filesystem path, but on Windows that means `github.com\owner\repo`, disagreeing with the always-forward-slash convention every category pattern and doc example assumes. We now render these specific relative identifiers (never absolute filesystem paths, which still use `Path::display()` unchanged) by joining `Path::components()` with `/` explicitly (`repo_walk::display`), regardless of platform.

**Consequence:** `gig list`/`gig cd`/debug output is copy-pasteable straight into a `gig config category` pattern on any OS. This is a deliberate, narrow exception to "just use the native path type": anywhere gig prints a location a user might actually navigate to (e.g. `gig cd`'s final printed absolute path, `Cloning ... into ...`) still uses native separators, since those need to work as real paths, not identifiers.
