# Scope shell completion to bash/zsh/fish, structural only

`gig` is gaining a `completion` subcommand (`gig completion <shell>`) that prints a `clap_complete`-generated script for the user to source. `clap_complete`'s `Shell` enum supports five shells (bash, zsh, fish, elvish, powershell), and clap separately offers a dynamic completion mechanism that can complete runtime *values* (e.g. our declared category names, or already-cloned repo paths) by calling back into the binary per keystroke. We deliberately narrowed both: the `shell` argument accepts only `bash`/`zsh`/`fish` via our own enum, not `clap_complete`'s full `Shell` set, and completion covers only subcommand/flag *names* via static `generate()`, not dynamic values.

**Consequence:** restricting the shell list avoids advertising elvish/powershell support in `--help` that we haven't verified; widening it later is a small change since `generate()` already supports them. Dynamic value completion (e.g. completing category names in `config category <name>`) is a materially heavier feature - a different clap API and a different sourcing model (the shell calls back into `gig` live) - not an incremental extension of this design, so it's deferred rather than built speculatively.
