# Inherit stdio for git clone/pull instead of capturing output

`get` is gaining its own status messages ("Cloning... " / "Cloned into...") around `git clone` and `git pull`, but until now `git_ops::clone` used `Command::output()`, which captures (and thus swallows) git's own stdout/stderr entirely - the user only saw it quoted back inside a `git-get` error message on failure, never git's live progress. We decided `git_ops::clone` and `git_ops::pull` should both switch to `Command::status()` with inherited stdio, so git's own output (clone progress, pull diffstat, `Already up to date.`, etc.) streams directly to the user - consistently for both operations, not just pull.

**Consequence:** this trades away the ability to quote git's stderr text in git-get's own failure message, since inheriting stdio and capturing output are mutually exclusive. On failure, git's own error is already visible on the inherited stream, and git-get's own error becomes a plain `git clone/pull ... failed (exit code N)` rather than re-quoting stderr - deliberately not duplicating what the user already saw. `git_config`'s `get`/`set_global` are unaffected and keep capturing output, since their output is meant to be parsed (`get`) or is uninteresting (`set_global`), not watched live.
