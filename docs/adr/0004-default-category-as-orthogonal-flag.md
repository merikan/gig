# Default category as an orthogonal flag, not a special pattern

Routing an unmatched clone somewhere other than bare `root-dir` used to require a category with a catch-all pattern (e.g. `.*`) declared *last*, since `category_routing::resolve` is first-match-in-declaration-order - a catch-all declared anywhere else silently shadows every category after it. We're replacing that footgun with an explicit `--default` flag on `gig config category`: a category so marked is used whenever no declared category's pattern matches (its own included), regardless of where it sits in declaration order. `--default` is orthogonal to patterns rather than a special pattern value or a `--flag-only`-style constraint - a category can carry real patterns *and* be the default, matching normally by pattern first and only falling back to "is default" when nothing (including itself) matched. At most one category can be default at a time; marking a new one auto-demotes the previous, printing a warning, mirroring the existing destructive-replace warning `config category` already prints when a plain pattern-list replace drops prior patterns. Unsetting is explicit (`--no-default`, a no-op if the category wasn't already default) rather than only reachable by promoting a different category, so "no default at all" stays reachable. `--default`/`--no-default` are mutually exclusive with `--add`: default-status changes are always a separate command from pattern-list mutation, keeping the flag interactions `config category` has to validate small.

**Consequence:** the old catch-all-pattern-declared-last convention keeps working unchanged (nothing about `category_routing::resolve` or pattern semantics changes) - `--default` is documented as the recommended replacement, not a breaking migration. `resolve_destination_root`'s fallback path grows a second case (declared default vs. bare `root-dir`), but `find_existing_clone`'s non-destructive candidate search needs no change: it already probes every declared category's destination unconditionally, default or not. `config category`'s list/view output gains a third tab-separated column (`default`, present only on the default category's row(s), repeated per pattern row) - a format choice made now, while the column count is still small, rather than overloading the name or pattern field later.
