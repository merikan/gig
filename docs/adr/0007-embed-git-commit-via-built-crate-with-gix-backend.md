# Embed git commit via the `built` crate, `gix` backend

`gig version` and `-V`/`--version` need to show the commit they were built from, not just the crate version. We embed this at compile time rather than shelling out to `git` at runtime (which would break for a relocated/packaged binary with no `.git` nearby). We use the `built` crate from a `build.rs` rather than hand-rolling a `git rev-parse` call there, since `built` already handles the edge cases (no `.git` directory, shallow CI checkouts, dirty working tree) and degrades to `None` instead of failing the build. `built` offers two interchangeable git backends: `git2` (links libgit2, typically needs a C compiler/cmake) and `gix` (pure Rust). We picked `gix` to avoid adding a C-toolchain build requirement for something this small. The resulting string is `<version> (<short-commit>[-dirty])`, or `<version> (unknown)` when no commit could be determined; `-dirty` is appended when `built`'s `GIT_DIRTY` reports uncommitted changes at build time.

**Consequence:** `Cargo.lock` picks up `gix` and its dependency tree as build-dependencies (dev/build-only, not shipped in the binary's runtime dependency graph). A build with no git info (source tarball, `cargo install` from a packaged crate) still succeeds, just showing `(unknown)` instead of a commit - never a hard build failure. Because the commit and dirty state are baked in at compile time, they reflect the state of the tree that was *built*, not necessarily the tree currently on disk if source has changed since.
